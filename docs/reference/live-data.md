# Live data

The standalone window also saves UI-only position, size and maximization preferences in the launcher's persistent add-on data directory (`retro-window.json`), independently of installed add-on versions. No telemetry or game images are written by this feature.

Team badges and fitted-tyre images come from Swofty's image service for the current vehicle, including F2 and other game/add-on definitions. Compound IDs are active GameDB stat IDs rather than an F1-only enumeration. Image records are accepted only for the matching telemetry generation and car identity; display waits for a named driver, without requiring optional position or compound-number readings. A missing image remains unavailable rather than being replaced with an invented icon.

- Driver positions and the display names supplied by Swofty’s Live State API, including the player’s name for human drivers. Names are shown as supplied, without splitting or reformatting. Choose either the full grid or your car and the nearest four cars. Nearest shows two ahead and two behind, shifting towards the available cars at either end of the grid.
- Only vehicles positively identified as racers by Live State are included. Safety cars and other non-racing vehicles are excluded, independently of their name or vehicle slot.
- A small team logo between position and driver, using Live State’s badge reference and image service. Catalogue teams and runtime My Team references use the same interface. Missing or pending images leave a blank cell without waiting for an image to load. Badges are displayed only once that row’s name, current position and tyre compound are known. Images preserve transparency and aspect ratio and stay in memory. Runtime capture is armed at add-on load and retried during startup, before entering a session, so My Team textures rendered in menus can be observed. While the table is gated during loading, available Live State racer references are used to request and poll badge images early, once per unique reference per pass. This prefetch never publishes driver rows or bypasses snapshot synchronization.
- The fitted tyre’s icon from Swofty 1.10.9 Live State v6 `tyre_icon_texture` and its image service. This replaces the add-on’s compound label/coloured-circle indicator in all session views. Pending, unavailable or invalid images show a dash; no stock-letter or guessed-colour fallback is used. Icons stay in memory, preserve transparency/aspect ratio and follow image reference/revision changes.
- A session label in the existing page subtitle: Practice 1/2/3, short practice, qualifying and sprint qualifying formats, Sprint, Race or Time Trial. Live State supplies the numeric type. Swofty’s session context distinguishes Sprint from Race; if that context is unavailable for the ambiguous race ID, the label reads **Race / Sprint (unconfirmed)**. Missing data stays **Unknown**. Session labels clear with the table when the session ends.
- Timed practice, qualifying and sprint qualifying sessions show the game’s remaining time as **MM:SS remaining**, when the verified ruleset getter is available. Sprint/race sessions show **Lap current/total** using the race leader’s progress and the current ruleset distance. Current lap comes from Live State; the remaining-time getter and total race distance use checked named bindings. Counters remain absent when unavailable; they do not use UDP or a locally simulated countdown.
- The session label and counters share the existing subtitle to avoid adding a separate block above the table. The launcher controls page scrolling; smaller windows, larger grids or open setup cards may still require it.
- Practice tables show Pos, team badge, Driver, Tyre, completed Laps, Last lap, Best lap, Status and Setup.
- Qualifying and Sprint Qualifying add Gap to best, calculated from the fastest valid lap across the entire current session, including cars outside a nearby-driver window. Known disqualified cars are excluded from that benchmark. S1, S2 and S3 show the sectors belonging to each driver's best lap, using the existing timing data; these are not independently fastest sectors. They are visible by default in both display modes and can be hidden or resized through existing column preferences.
- Sprint and Race tables show Pos, positions gained/lost from the starting grid, team badge, Driver, Tyre, Tyre age, Gap ahead, Last lap, Best lap, S1/S2/S3, FL/FR/RL/RR/Avg wear percentages and Status. The three sectors belong to the same last completed lap shown in Last lap, including completed invalid laps; they are not individual sector records. Qualifying continues to use best-lap sectors. Race tables have no setup controls. Tyre age is supplied by Live State v6 `car_detail`, including previous stints on the fitted set within the current session. The inspected launcher calculation does not carry usage from qualifying into the race: a used set can show zero at race start. The add-on does not convert wear into an invented age or add a private-reader fallback. It is not calculated from pit visits, compound changes or wear. Known zero is displayed as zero; unavailable age stays a dash. Updates and Flashback follow the core snapshot, with no add-on stint history or recorder. Existing saved stint-column visibility and width migrate to Tyre age.
- Status has its own column. DNF (did not finish or retired) and DSQ (disqualified) take priority over Pit; otherwise known results show Run, Finished or NC. Unavailable status remains a dash. DNF/DSQ rows use muted text, including the player's row; tyre colours and badges remain visible. The launcher table API does not expose whole-row opacity.
- In Practice, Qualifying and Sprint Qualifying, an observed pit exit shows **Out** (**OUT** in retro) until that driver completes the lap. This is inferred from Live State pit-lane status and completed laps, not a dedicated outlap flag. PIT, DNF and DSQ keep priority; Sprint/Race statuses are unchanged. One small observation per car is kept in the native publisher at its existing sampling rate, independently of display mode, nearby selection and column visibility. Unknown inputs, missing/replaced cars, session changes and detected lap-count rewinds clear the inference. A car first observed already on track stays RUN until an actual pit visit is observed. No reader, recorder or persistent telemetry file is added.
- Practice and qualifying retain the setup toggle and card beneath each driver, showing wings, differentials, camber, toe, suspension, anti-roll bars, ride heights, brakes, all four configured tyre pressures and fuel remaining. Unavailable readings show a dash. Fuel remaining is the current tank value, rather than the original setup fuel load.
- Last completed lap and best valid lap are shown in every layout. Unavailable readings stay as dashes. Zero completed laps and a known zero race interval remain valid values. Time Trial and unknown session types use the basic practice layout.
- Three switches in the normal add-on settings enable Practice, Qualifying/Sprint Qualifying and Sprint/Race views independently. All default to enabled; disabled groups show a message instead of a fallback table.
- The header **Columns** button expands a selector above the live table. All fields, including position, badge, driver, setup and the subtitle counter, can be hidden. Changes save immediately for the current profile and session group; the table previews changes immediately, clicking **Columns** again collapses the selector, and **Reset defaults** restores that group. An all-hidden table shows a recoverable message. A session-group change closes the selector; stale events cannot change the next group.
- Optional highlighting of your own row. Display settings are in Swofty's add-on settings.
- Driver, wear and lap-time columns automatically share the available width when the launcher is resized or maximised. Narrow windows can still truncate content; maximising gives these columns more room.
- The table stays empty at the career trackside workstation and during session loading/unloading. Values appear in the actual session's garage or grid. Pausing an active session retains current values. Session end/unload clears them; closing the game releases the shared snapshot.

## Processes and local files

On Windows, Swofty starts **`telemetry-live.exe`**, a helper that displays the optional retro window or serves the launcher page. It communicates with Swofty through local input/output pipes. Swofty loads **`telemetry-live.dll`** inside the game using its normal native add-on system. The DLL uses Swofty 1.10.9’s Live State v6 API for player identity, names, position, result status, session type, tyre compound, pit-lane status, starting grid, tyre wear/age, completed laps, last/best lap times and sectors, penalties and gap ahead. CarOps supplies car count/handles, fuel, brake pressure and brake bias. The replaced private readers have been removed. Only remaining setup values and session-ruleset fields retain checked direct readers. Session countdown and total laps are declared but not populated by Live State v6, so their existing verified binding path remains. Sprint/Race context and lifecycle also retain Swofty hooks. The raw grid, wear and lap-history readers, timing hooks/cache and inferred stint counter have been removed. The add-on does not change car settings or game files.

Live State availability depends on Swofty's verified layouts for the running game build. Missing individual readings stay unknown. An unavailable or changing snapshot retains the last display until fresh data returns or the session ends; there is no private-reader fallback for API-covered values. The older telemetry API, which can include UDP data, is not used.

The DLL publishes a fixed **10,752-byte telemetry snapshot (private wire version 5, with separate last/best sector triplets)** and an optional **1,066,528-byte image snapshot** in Windows. The image buffer holds at most 64 images (one team badge and one tyre icon per car) of up to 64 × 64 RGBA pixels. Both buffers share a publication sequence, including tyre icons. The helper copies them under the same generation check and only commits a complete matched view; a concurrent update retains the previous view. Session end clears immediately even if the badge buffer is busy. The helper opens the buffers read-only and displays the latest matched values. There is no network listener, web server, separate recording process, Python runtime or installed Windows service. The add-on retains current values and at most 64 encoded badge/tyre images. PNG conversion is reused while the image reference, dimensions and revision stay unchanged. Session and car identity checks prevent a previous session’s or replaced car’s badge appearing in a new row. No game resources are extracted to disk.

On native Linux, Swofty starts **`telemetry-live-linux`** and supplies the game-copy add-on path through `addon_game_dir`. Under Wine/Proton, the DLL additionally mirrors the same frames into one temporary file-backed shared mapping in its game-copy `bin/` directory. The Linux helper maps only this add-on-owned file read-only. The file is not a recording: it has fixed capacity, is overwritten by the latest snapshot and uses delete-on-close. No extracted PNG, game archive or historical telemetry is saved. The Windows named mappings are retained.

The helper exits when Swofty closes its communication pipe. Disabling the add-on clears its display and closes the helper's snapshot handles; Swofty may keep the helper process running. A native component already loaded in a running game remains there until that game closes. Restart the game after enabling, disabling or updating a native add-on.

v0.5.10-test.4 writes only small `columns-<profile>.json` UI-preference files in the launcher-provided add-on data directory. Writes use a temporary file and atomic replacement; save failures are reported without applying unsaved choices. There are no telemetry recordings or extracted image files; the Linux/Proton bridge uses the temporary binary IPC mapping described above. Swofty manages its profile settings and normal launcher logs. Existing data in **Documents/F1 Game Telemetry** is left untouched, but this live-only version does not open or analyse those recordings. Nothing is uploaded by the add-on.

The retro window additionally waits for the actual game-flow node `GridRundownType`, `PreRace`, `ZoomToMonitorCutscene`, `BeginGameplay` or `InGame`, supplied by Swofty’s `flow.state` event. A fresh snapshot or `session.start` alone does not open it: car data can already be readable behind session selection. Readiness is latched through pauses and cleared on the existing session/hub/loading boundaries. This window-only flag does not change acquisition or launcher data.

The grid/pre-race and garage transitions allow the retro window to appear before racing begins. `BeginGameplay` alone is too late in races: it can coincide with lights out. Intro-camera and session-start events alone still do not authorize opening.

Qualifying drop-zone highlighting applies only in Q1/Q2 and SQ1/SQ2. Until Swofty exposes the actual advancement cutoff, it uses the user-selected calculation from the full racer field: Q1/SQ1 removes half the excess over ten (rounded down); Q2/SQ2 advances ten. A 24-car field therefore uses P18 onward and P11 onward. These are calculated thresholds, not the game's verified rules; custom qualifying formats may differ. Q3/SQ3, short/one-shot qualifying, unknown positions and known DNF/DSQ/NC/retired drivers are not marked at risk. The retro view uses a red row background; the launcher view uses its built-in bad row tone. When Highlight my row is enabled, the player's blue/accent highlight takes priority over the elimination colour and the retro player arrow remains visible. Other at-risk drivers stay red. Turning Highlight my row off allows the player's row to use elimination red too. Column visibility and nearby-driver mode do not alter the cutoff.

Qualifying/Sprint Qualifying and Sprint/Race have a PEN column before Status, visible by default and included in saved column controls. It shows Live State's current classification time-penalty total (`5s`, `5.25s`) and pending drive-through (`DT`) and stop/go (`SG`) counts, such as `5s+2DT+SG`. Time totals use the classification availability flag and finite range checks; DT/SG use `SWOFTY_LIVE_HAVE_PENALTIES`. A dash means no reported penalty or unavailable data. The time total is displayed at the user's request and is not claimed to be an unserved-only balance. Warnings and stop/go durations are omitted. Grid penalties awarded during qualifying should be shown until applied to the race grid, but this still requires a reliable exposed source: the checked released Live State has no grid-penalty field, and `session.penalty.issue` is a non-firing shell event. No grid penalty is inferred from positions. No new memory reader or recorder was added. Private wire v5 carries the millisecond time total; restart the game and helper after updating.

The add-on settings include **Sliding row animation (retro window)**, on by default. Swofty saves the toggle per profile. Disabling it cancels an active slide and settles rows in their current order; later position changes jump immediately. Re-enabling restores sliding for later changes. The setting applies on the next helper refresh without restarting or recreating the window, and does not change the launcher table.

Driver order uses Live State’s `SWOFTY_LIVE_SHAVE_ORDER` classification array from the same coherent snapshot as the car data. The native component validates its length, IDs, uniqueness and coverage of every published racer; non-displayed vehicles, including the safety car, are filtered out. A validated order is preserved by both frontends before selecting the nearby-driver slice. Unavailable, incomplete or malformed arrays retain the previous stable sort by current position, starting grid, then vehicle ID. Row IDs remain vehicle/session/identity-based, so position-change animations and setup controls remain associated with the same driver. This change applies only to the active 0.6.0 source.
